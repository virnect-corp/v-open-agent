v-open-agent 구성도
docs/SPEC.md v0.3 기준

입력이 서버로 들어가 경고가 되기까지

스마트글래스의 입력과 출력, 로컬 엣지 서버와의 연결, 서버 안의 모듈 배치, 관측 한 건이 결정과 기록으로 바뀌는 흐름을 그림 두 장으로 정리했습니다.

스마트폰은 입력 경로가 아닙니다. 글래스가 Wi-Fi로 엣지 서버에 직접 연결하는 것이 이 프로젝트의 전제입니다. MVP-1에서는 실제 글래스 대신 시뮬레이터가 같은 WS 프로토콜로 접속합니다. 스마트폰은 나중에 상태를 조회하는 화면 정도로만 검토 대상입니다.

1. 구성도 — 장치 연결과 서버 모듈 배치

글래스 입력

  • camera_0, MVP: 시뮬레이터가 프레임마다 Draft를 보냄 / Stage C: 실기기가 JPEG 프레임을 보내고 서버가 탐지/추적
  • imu_0, Stage C: 카메라 움직임 보정용. 보정에 실패하면 이동 물체 판단을 보류
  • mic_0, ptt_0, Stage D: 소리 이벤트, 버튼을 누른 동안만 음성 명령
  • 자가진단, MVP: 센서 오류/복구를 health로 보고

글래스 출력

  • hud, 경고 문구 표시, "감지 제한" 상태 표시
  • speaker, 장치 내장 TTS로 문구 낭독. TTS가 없으면 경고음
  • haptic, 경고와 고지를 다른 진동 패턴으로
  • ACK: received는 수신 직후, played는 출력이 하나라도 끝난 뒤

연결 감시

  • 서버는 1초마다 heartbeat를 보냄
  • 글래스가 3초 동안 아무 메시지도 못 받으면 내장 문구 "서버 연결이 끊겨 경고를 받을 수 없습니다."를 직접 출력
  • 1/2/4/8초 간격으로 재접속한 뒤 resume
  • 출력 장치를 하나도 선언하지 않은 글래스는 세션을 열 수 없음
  1. 글래스가 POST /v1/sessions로 장치 ID, 비밀값, 입력/출력 capability를 보내고 세션 ID, 토큰, heartbeat 주기를 받습니다.
  2. /v1/streams/{session_id}로 WS에 연결하고, 5초 안에 첫 메시지로 토큰을 보냅니다. 늦거나 틀리면 연결이 끊깁니다(4401).
  3. 프레임마다 ObservationDraft를 보냅니다. 감지된 물체가 없어도 보냅니다.
  4. 서버가 관측 ID와 수신 시각을 붙여 엔진에 넣고, 100ms마다 tick도 호출합니다.
  5. 상태가 바뀌면 decision을, warning이 되면 alert를, 진행 중이던 위험을 더 판단할 수 없게 되면 notice를 같은 WS로 내려보냅니다. 1초마다 heartbeat도 보냅니다.
  6. 글래스는 선언한 출력으로 경고를 내보내고 received와 played를 구분해 ACK를 보냅니다. 재접속하면 아직 유효한 경고만 다시 받습니다.
